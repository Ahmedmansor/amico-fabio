المستخدم اللاحق بتثبيت الثيم الوحيد، صارت ألوانها مراجع إلى `theme.css` أيضًا؛

محتوى الحملة في الهوم لا تعني إعادة تصميم الحملة أو تغيير مسار استقبال طلباتها.

## الهيدر والفوتر المستهدفان

الهيدر أبيض نظيف، الشعار والنص بالكحلي، وروابط واضحة مع active state، وزر
«خطط رحلتك» بالبرتقالي. قائمة أساسية قصيرة للهوم والرحلات والبلوج والدليل عند
توفره؛ روابط التقييمات وSharm Secrets تظل متاحة في القائمة الثانوية أو الفوتر.
لا نفقد أي وجهة قديمة عند تقليل ازدحام الشريط. الحساب والمفضلة واللغة من
مكوناتهم الحالية؛ نغيّر عرضها ونحافظ على تحميل الجلسة والعدّاد والوجهات.

الموبايل: الشعار، الإجراءات الضرورية، وقائمة واحدة تجمع باقي الروابط وزر
التخطيط. لا نحشر كل أزرار الديسكتوب في صف صغير. فتح/إغلاق باللمس والكيبورد،
Escape وإرجاع focus، وعدم حجب المحتوى أو عناصر الحساب. اختيار sticky بدل
fixed مبدئيًا لتقليل تعويضات الارتفاع، بعد مراجعة ارتباطات الصفحات والعروض.

الفوتر يحتفظ بالمحتوى الحالي: نبذة Fabio، البريد، الشبكات، الروابط القانونية،
الشعار وCross Roots ونص الإرث. يُنظم في أعمدة ومسافات موحدة على سطح كحلي من
الثيم ونص فاتح، مع إضافة وجهات الموقع الضرورية دون حذف المحتوى. موبايل بترتيب
قراءة طبيعي؛ لا حاجة إلى accordion يخفي روابط قليلة. نفس الفوتر في البلوج.

عقد المكونات المقترح: locale، معرّف القسم الحالي، وخريطة روابط لغة فعلية من
الصفحة/الـlayout. `Header` يعرض الخريطة ولا يخمن slug المقال باللغة الأخرى.
يبقى SEO وcanonical/hreflang في طبقة SEO؛ روابط التنقل ليست بديلًا عنها.
الـlayouts تبقى متخصصة في تركيب الصفحة ولا تتحول إلى ملف كبير بعشرات flags.

## UI/UX Pro و21st

قُرئت مهارة UI/UX Pro وشُغّل بحث design-system، ثم أُعيد بحث أضيق لأن النتائج
اقترحت Liquid Glass/Aurora ولوحات مختلفة عن هوية الموقع. لا نعتمد هذه النتائج
كهوية؛ نعتمد قواعد المهارة العامة للتباين، التنقل، اللمس، الأداء وreduced-motion.
بحث stack Astro أعاد توجيه static HTML مناسبًا للمعمارية الحالية.

مرجع 21st: https://21st.dev/ ؛ المكتبة تعلن React/TypeScript وTailwind.
نستفيد من أنماط التنقل، إبراز الرابط النشط وhover البطاقات، وننفذها محليًا
بـAstro/CSS وVanilla JS عند الضرورة. لا إضافة React أو Framer Motion.
عند اختيار مثال محدد نسجل رابطه وترخيصه قبل نسخ أي مصدر؛ لم يُختر مكون محدد بعد.

اللمسات المقترحة للديسكتوب والآيباد: underline متحرك خفيف للرابط، انتقالات
150–220ms للون/الظل/transform، وظهور قائمة سلس. التابلت يعتمد على عرض المحتوى
وليس اسم الجهاز؛ لا وظائف تعتمد على hover فقط. تأثيرات hover تحت
`(hover:hover) and (pointer:fine)`، وجميع الحركات تحترم reduced-motion.
الموبايل يعرض المحتوى مباشرة بلا parallax أو shader أو scroll-scrub أو فيديو
autoplay. لا إخفاء مكون ثقيل بـCSS بعد تحميله؛ الشِل لا يحتاج runtime UI جديدًا.

## مراحل التنفيذ ومعايير الإغلاق

1. **خط أساس:** حصر مستهلكي الشِل وعقود DOM والروابط؛ لقطات النسخة الحالية
   IT/EN بعروض 375/768/1280، و320px لفحص الازدحام. تقرير فرق محتوى وخط أساس
   للأداء. اللقطات محلية ignored، والتقارير/scripts فقط في Git. حفظ مرجع بصري
   مستقل للنسخة المعتمدة قبل redesign؛ ملفاته خارج تاريخ Git وتوثيق مكانه محليًا.
2. **نظام التصميم:** تثبيت palette الحالية وإضافة tokens للمقاسات والخطوط
   والعرض والحركة؛ توثيق استعمالها وأزواج التباين. نقل قواعد الشِل إلى ملفات
   مستقلة، بدون فرض reset البلوج على الرحلات أو الحملات.
3. **الهيدر الموحد:** تطوير `Header.astro` وأجزاء صغيرة للشعار والتنقل والإجراءات
   عند الحاجة، ثم ربطه بالـlayoutين. فصل سكربت التنقل عن تهيئة الحساب وترك
   ملكية الجلسة والعدّاد للـfeatures المعنية. مقارنة الحساب guest/loading/signed-in،
   المفضلة، اللغة والكيبورد والموبايل. لا حذف أي سلوك مبكر قبل توفير مكافئه.
4. **الفوتر الموحد:** تلميع الحالي وربطه بالـlayoutين، تحديث الروابط المشتركة
   من config/i18n، وإزالة markup وCSS الفوتر المكرر بعد التحقق.
5. **توحيد الصفحات:** الهوم أولًا، ثم الاستكشاف والتفاصيل والباقات، ثم بقية
   صفحات الشِل. استبدال hardcoded colors والخلفيات القديمة على دفعات محددة،
   وضبط typography والبطاقات والحقول دون تغيير حساب الأسعار أو ترتيب التوصيات
   أو نصوص الحجز. إزالة قواعد legacy التي لم يعد لها مستهلك فقط.
6. **إثراء الهوم:** مراجعة جدول محتوى الحملة، إدراج الجزء الصالح فقط، وربط CTA
   بالمخطط القائم. الحفاظ على الأقسام والمراجعات والوجهات والعرض الحالي وقاعدته
   `is_active`؛ أي دمج أو إعادة ترتيب يوثّق في مقارنة قبل/بعد.
7. **لمسات الشاشات الكبيرة وQA نهائي:** إضافة الأنماط المختارة من 21st بعد استقرار
   الأساس، ومقارنة جميع عائلات الصفحات دون تحميل تكلفة إضافية على الموبايل.

كل مرحلة تنفيذ مهمة مركزة: فحص diff، تشغيل `npx astro check` و`npm run build`
من `astro-site/` باستخدام Node المثبت بالمشروع، وإظهار المخرجات الحقيقية، ثم
commit بملفات المهمة فقط. اختبارات domain عند تغيير logic ورسائل WhatsApp؛
لا إعادة تشغيل حزمة Auth/البريد البعيدة بسبب تعديل CSS. الخطة
تسجل المراحل المقترحة؛ نتائج التنفيذ الفعلية منفصلة في تقرير QA المشار إليه أعلاه.

## قائمة القبول

- مكوّن هيدر ومكوّن فوتر للموقع الأساسي، مع فصل الحملات المقصود.
- لا فقدان نص/صورة/سعر/رابط؛ تقرير أي فرق مقصود أو نقص على كل صفحة ممثلة IT/EN.
- لغة المقال/الدليل تفتح المقابل الحقيقي، وتنقل الهوم والرحلات يظل صحيحًا.
- لا تعطل Google/email login أو welcome أو sync أو consent؛ لا تغيير backend.
- فحص الهيدر عند 320/375/768/1024/1280 و200% zoom، focus واللمس وEscape
  والحالة النشطة، offsets الروابط الداخلية والعرض وطبقات dialogs.
- شِل واحد في DOM، لا listeners مكررة، لا console errors جديدة أو overflow أفقي.
- مقارنة الأداء قبل/بعد بنفس الإعدادات: هدف LCP ≤2.5s وCLS ≤0.1؛ INP ≤200ms
  هدف بيانات استخدام فعلية، ولا ندعي إثباته بنتيجة Lighthouse وحدها. لا زيادة
