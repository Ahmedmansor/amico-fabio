## Cloudflare Turnstile

اعمل Managed Widget وأضف أسماء المضيفين بدون https أو مسارات:

- `amico-fabio-iyzo.vercel.app` — ده عنوان نسخة الاختبار الفعلي، واسم مشروعها `amico-fabio-test`.
- `localhost` و`127.0.0.1` للتجربة المحلية.
- أي preview hostname مختلف لازم يتضاف صراحة لو هنختبر عليه.

الـ Site Key علني، ويمكن إرساله للأجنت لوضعه في
`PUBLIC_AUTH_TURNSTILE_SITE_KEY`، أو `TURNSTILE_SITE_KEY` الموجود محليًا. الـ Secret Key يتحط داخل Supabase
Authentication → Attack Protection فقط، ومش مطلوب إرساله في الشات أو وضعه
في ملفات المصدر أو متغير يبدأ بـ PUBLIC.

تفعيل CAPTCHA لازم يتزامن مع نشر صفحة الدخول الجديدة اللي بتبعت التوكن.
النسخة المنشورة القديمة مش بتبعته، فتفعيل الحماية عليها قبل تحديثها يعطل
طلب رابط البريد. لو فعلته بالفعل، هنكمل نشر النسخة المطابقة بعد وصول Site Key؛
مش هنوقف الحماية أو نتجاوزها. الموقع الإنتاجي القديم مش ضمن التغيير.

## نقطة التسليم للأجنت

بعد الإعداد، المطلوب Site Key العلني وتأكيد تفعيل Turnstile داخل Supabase.
ما تبعتش Secret Key أو client secret أو service_role أو access token.
هنراجع الإعدادات الفعلية ونطابقها مع النسخة قبل تفعيل flag الباسورد.
Confirm email يفضل ON؛ سياسة الباسورد المستهدفة 12 حرفًا على الأقل.

الموافقة التسويقية ليها SQL مستقل وflag مغلق. الملفات متحضّرة محليًا ولم تُنفّذ
على قاعدة البيانات. لازم اختبارات الملكية والأدوار والتزامن الحقيقية تنجح
قبل تفعيلها. موافقة تذكير المفضلة القديم مش موافقة على عروض أو خصومات.
مفيش إرسال تسويقي جديد، ولا تغيير في نطاق مستلمي التذكير الحالي.

الدخول العادي بالباسورد أو OAuth لا يحتاج رسالة دخول؛ تأكيد التسجيل، وإعادة
طلب الرابط، ونسيان الباسورد قد يستهلكوا رسائل. التفعيل يثبت التحكم في البريد
وقت التأكيد، ولا يضمن وجوده للأبد أو اكتشاف كل بريد مؤقت أو ارتداد صفر.

بعد إعداد المفاتيح، اختبار القبول الحقيقي يكون بعنوان يختاره المستخدم:
تسجيل وتأكيد بريد، خروج ودخول بالباسورد، رابط دخول لحساب موجود، Google،
رجوع للصفحة المطلوبة، بقاء المفضلة، ثم اختيار الموافقة وسحبها. نجاح الاختبارات
الوهمية الحالي مش دليل وصول رسالة جديدة أو نجاح OAuth الحقيقي.
